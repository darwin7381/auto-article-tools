## 對平台模型的修正含義(重要)

1. **幣別是 USDT,不是 NT$** —— 我的 ITEM_PRICES(NT$ 刊例)是錯誤假設。真實營收 = 合約金額(USDT),且**認列是照合約期程逐月攤提**(Cal-獎金期認列),不是「結案一件認列一件」。平台的營收引擎需要雙軌:合約攤提(財務真相)+ 件次×刊例(營運參考)。
2. **額度類別比平台多**:TG / FB / LINE 社群推播也是額度品項,還有 Custom。QUOTA_CATEGORIES 需擴充。
3. **客戶實體已存在**(Base-客戶):維繫層級、維繫狀態(談續約/正常執行)、項目類型、聯繫渠道 —— 客戶 360 應對齊這些欄位,之後可雙向同步。
4. **合約狀態機**:生效/結案/過期(+談續約在客戶層)。
5. **獎金層**:編輯獎金 per 品項(廣編已因 AI 化取消 —— 自動化已實際改變獎金結構!)、BD 獎金 = Revenue×15% 逐月攤提。平台終局要能算這個,才能真正取代這兩份表。
6. **n8n 已在寫 BD-1 Entry** —— 平台接手時要接管或並存這條寫入。
7. 合約編號雙軌:DM 用 `#25Qxxx`、BD 用 `#104xxxx`,`sheet_ref` 對回時要帶編號。
